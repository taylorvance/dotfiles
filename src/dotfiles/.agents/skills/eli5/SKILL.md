Re-explain the previous reply, or the part the user points at, so the user understands it well
enough to discuss it with colleagues, not just repeat it.

- Lead with the answer in one line, then only as much plain explanation as it takes for that
  line to make sense. Usually that's a few sentences, or one short line per item.
- Explain why, not just what: the reason it happens, or the reason the fix is right. That's
  what lets the user field a follow-up.
- Use plain words. Keep the terms colleagues will use when discussing it, and say what each
  one means in a few words.
- Pick a concrete example with real numbers over an abstract rule.
- If it's a problem, say what breaks, for whom, why it matters, and what the fix is.
- Keep the verdict, exact numbers, anything unverified, and anything the user has to do.
  If simplifying hides something that matters, say so.
- Stay in this register for follow-ups on the same topic.
