## 2026-08-26 Stay bespoke — no chezmoi/stow migration

- Status: accepted
- Topics: architecture, dotfile management
- Refs: `src/symlink-manager.sh`, `README.md`
- Decision: Keep the custom symlink manager and vendored-submodule plugin handling; no migration to chezmoi, stow, or any dotfile manager.
- Rationale: chezmoi's copy model breaks edit-from-either-side + nvim git integration (symlink transparency is the design's best property); submodules beat chezmoi externals for pinning + audit (`git log old..new`); the test breakdown showed ~65% of the suite guards the personal scripts, which survive under any manager — migration would delete little.
- Alternatives: chezmoi (better templating/adopt, wrong model); stow (same model, does less); bare git repo (rejected in 2020).

## 2026-08-26 Shell dialect layering

- Status: accepted
- Topics: scripting, portability
- Refs: `src/dotfiles/.local/bin/`, `src/dotfiles/.zsh/functions.zsh`, `CLAUDE.md`
- Decision: Three layers — POSIX sh where trivial (`sysinfo`), bash 3.2 for standalone scripts, zsh only for interactive shell-integration functions. No brew bash, no zsh migration.
- Rationale: `/bin/bash` 3.2 is frozen (stable target, exists on every macOS and Linux box); zsh scripts wouldn't run in bare containers; the 3.2 floor is now CI-enforced (macOS unit-test leg), so the constraint costs ~nothing.
- Alternatives: migrate scripts to zsh; require brew bash 5 + env shebangs (splits bootstrap vs daily scripts into two regimes).

## 2026-08-26 Conditional test selection via @covers headers

- Status: accepted
- Topics: testing, git hooks, CI
- Refs: `.githooks/pre-push`, `tests/`, `src/doctor.sh`
- Decision: pre-push runs only tests whose `# @covers <path|glob>` header matches a changed file; unmatched changes fail open to the full suite; doctor validates the headers; CI stays full-suite as backstop.
- Rationale: Declared map beats grep-derived (script names like `e` are ungreppable); staleness is contained by doctor + fail-open, not memory.
- Alternatives: grep-derived map; central map file; no conditioning.
- Accepted gap: a guarded optional dependency between dotfiles is unmapped until a test exercises it — a miss costs a CI failure email, not a blocked push.
- Scope note: the macOS CI job runs unit tests only — integration tests are container-shaped (86 native failures at time of writing). First native run caught a real bash 3.2 bug in envsync (`set -u` + empty arrays).

## 2026-08-25 Explicit media-command dependencies

- Status: accepted
- Topics: shell commands, optional dependencies
- Refs: `src/dotfiles/.zsh/functions.zsh`, `README.md`
- Decision: Keep media downloading out of the default installer; make `ytaudio` and `ytvideo` guarded functions that explain their `yt-dlp` and `ffmpeg` requirements.
- Rationale: The commands must be usable or self-explanatory without expanding the installer and Makefile into feature-specific targets.
- Alternatives: Add a `make install-media` target or install media tools by default.

## 2026-02-18 Docker-only test runs (backfilled 2026-08-26)

- Status: accepted
- Topics: testing, safety
- Refs: commit `8ebe5cb`
- Decision: Removed `make test-local` and `check-test-safety.sh`; all tests run in Docker.
- Rationale: Native runs needed a 151-line safety audit to prove tests couldn't touch the real filesystem; Docker gives that isolation for free.
- Alternatives: Keep the safety auditor; trust mktemp discipline.
